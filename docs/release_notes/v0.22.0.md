# 0.22.0 Release Notes

Released 2026-10-25. Changes since tag `0.21.1`.

## Workflows and layout

My projects, People, Groups, and Manage projects now start with Search or Show all. Paged results open a focused record card; Back preserves the previous search and page. Body directory columns have been removed. Headers, forms, and workspaces share a centered canvas. Administration separates memberships, account/security, project access, and availability into focused panels with draft protection.

Audit filters and actions align without squeezing labels. Results show evidence and integrity checks on demand. Journal entries have a dedicated reading layout, and saving opens the completed entry. Creation forms and exports use a consistent centered width. Keyboard, mobile, light/dark, and enlarged-text layouts follow the latest verified Sekura Design MCP 3.2.1 specification (commit `5812e9e81b3e3a5128f5863cf678b0edd2cf22c0`). Malformed query values are handled without conversion errors.

## Files

- Multiple selection and drag and drop: up to 10 files per entry, 5 MiB each, 20 MiB total.
- Upload progress, cancellation, retry, removal, and draft preservation. Files become permanent only when the entry saves successfully.
- Encrypted names and contents, integrity-checked downloads, and an atomic transaction covering the entry, files, and creation audits.
- Download access follows the entry's current permissions, project availability, and deletion status. Files are served as attachments, never inline; the application does not scan them for malware.
- Journal ZIP exports include selected CSV/JSON records, original file bytes, and a manifest of filenames, paths, sizes, and SHA-256 checksums. Export filters apply consistently to records and files.
- ZIP limits: 10,000 entries, 10 MiB journal text, 1,000 files, and 50 MiB file contents. Export smaller project/date scopes if needed. Exports are decrypted; protect downloaded copies.

## Validation

All 160 automated tests pass, including attachment authorization, encrypted persistence, integrity checks, transaction rollback, legacy SQLite upgrades, and cached-export session/role revocation. Browser checks cover search and paging, Back/history, independent drafts, file selection and drag/drop, cancellation/retry, protected downloads, ZIP contents, keyboard access, themes, and 320px/200% text layouts. NuGet, npm, and the final container image reported no known vulnerabilities at release time.

## Upgrade notes

Back up both databases and preserve the existing journal encryption key before upgrading. The application applies an additive `journal_attachments` table and index on startup, using the existing schema-upgrade mechanism for SQLite, SQL Server, and PostgreSQL. The database account needs permission for this schema change. Existing entries need no conversion; they start with no attachments. Files reside in the application database, so existing database backup procedures include them.

No new configuration or dependencies are required. The .NET SDK/runtime and deployment requirements from [0.21.0](v0.21.0.md#upgrade-notes) still apply. SQLite upgrades and file round trips are covered by automated and browser tests; live SQL Server/PostgreSQL deployment validation remains environment-specific.
