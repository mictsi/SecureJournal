# 0.23.0 Release Notes

Released 2026-10-25. Changes since tag `0.22.0`.

## Journal reading and creation

Project entries display date, author, and subject together in a compact desktop row. **Show entry** expands the full description, notes, deletion information, and file downloads inline. The dedicated detail page shares the same content component. **Quick read** displays full entry content for the current page without editing actions; filtering, sorting, pagination, and return links preserve the reading mode.

Adding an entry from a project displays its name and code as fixed context instead of a dropdown. The primary New journal entry navigation link also preserves the opened project. Saving enforces that project even if a posted draft contains a different ID. Starting from the global composer without a project still requires an explicit project choice; an invalid project link cannot fall back to another project.

Audit activity now appears in the order **Date, Project, Who, Status, Action, Message**, followed by **View details**. Full messages, linked evidence, and integrity checks remain available. On narrow screens, the same fields wrap with visible labels.

## Files and upgrades

The per-file limit is **10 MiB** (shown as 10 MB in the interface). The existing limits of 10 files and 20 MiB total per entry remain unchanged. Download and ZIP-export behavior is unchanged.

Back up both databases and retain the existing encryption key before upgrading. Startup upgrades the old 5 MiB database constraint to 10 MiB on SQLite, PostgreSQL, and SQL Server. SQLite rebuilds the attachment table in a transaction while preserving encrypted rows, indexes, triggers, and foreign keys; a failed upgrade rolls back and restores foreign-key enforcement. The database account needs the applicable schema-change permissions. No new packages or configuration are required.

Older releases cannot read attachments larger than 5 MiB. A rollback after saving larger files requires restoring the pre-upgrade database backup or remaining on a compatible release.

## Validation

All 171 automated tests pass, including fixed-project saves, safe return links, old-schema attachment preservation, exact file-size boundaries, and upgrade rollback. Browser checks cover inline and quick reading, real pagination, project context, files, audit details, keyboard operation, mobile layouts, themes, and 200% text. Migration DDL was additionally exercised against PostgreSQL 18.6 and SQL Server 2022 for fresh and legacy schemas, repeated startup, size enforcement, existing ciphertext preservation, and cascade behavior.
